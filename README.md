# jordangrieve.com

My portfolio: a small, static Next.js site with case studies for the work I
want a hiring manager to see. Live at [jordangrieve.com](https://www.jordangrieve.com).

![Home page](public/images/jordan-hero-image.png)

## Stack

- Next.js 15 (App Router), React 19, TypeScript
- The design system's own CSS (`src/styles/nocturne.css`) plus plain CSS. No Tailwind, no CSS-in-JS
- `next/font` for Inter and Anton
- A self-hosted subset of the Phosphor icon font, generated by `scripts/build-icon-font.mjs`
- Every route is prerendered at build time; Vercel hosts it

## Routes

| Route          | Page |
| -------------- | ---- |
| `/`            | Home |
| `/work`        | Projects, with client-side filter chips |
| `/work/[slug]` | Case study |
| `/about`       | About, with the timeline |
| `/contact`     | Contact |

`robots.txt`, `sitemap.xml`, `llms.txt`, the Open Graph images and the icon set
are all generated routes under `src/app/`.

## What was hard

**Porting a container-query design without redrawing it.** The design was
built inside a fixed-width preview frame with `container-type: inline-size`,
so every measurement is in `cqw` units and its one breakpoint is a container
query at 640px. Rather than translate hundreds of values to viewport units,
`.wrap` in `src/styles/globals.css` plays the frame's role, capped at 1500px
and full-width below that, so the original sizing maths still holds. One
consequence: the mobile drawer is portalled to `document.body`, because
`position: fixed` inside a container-type element resolves against the
container rather than the viewport.

**Icons without a third-party request.** The site used to load the full
Phosphor stylesheet from unpkg: a render-blocking request to another origin
for roughly 1,500 icons, of which about 34 are used. The build script scans
the source for `ph-*` classes, subsets the font to those glyphs and inlines it
as a data URI in `src/styles/phosphor-subset.css`. The generated CSS is
committed, so a normal build needs neither the script nor its dependencies.

**Being findable by name.** Search and answer engines need the full name and
structured data, not a first name and a tagline. `src/lib/schema.ts` builds a
`Person` graph with `knowsAbout`, each case study gets its own generated Open
Graph image, and `llms.txt` describes the site for AI crawlers. The plan and
what each step changed are in `SEO-PLAN.md`.

## Where the content lives

All copy is plain TypeScript under `src/data/`. Edit there, not in the components.

| File              | Contents |
| ----------------- | -------- |
| `site.ts`         | Name, role, email, nav items, social links, the CV |
| `home.ts`         | Hero stats, services, toolkit, about timeline |
| `projects.ts`     | Projects, filters, featured selection, case-study bodies |
| `heroImages.ts`   | Case-study artwork |

A project with no matching case study 404s rather than rendering a stub, so
add both together.

## Run locally

```bash
npm install
npm run dev
```

Open http://localhost:3000. After adding or removing a `ph-*` icon class, run
`npm run build:icons` and commit the regenerated CSS.
