# jordangrieve.com

My portfolio: a small, static Next.js site with case studies for the work I
want a hiring manager to see. Live at [jordangrieve.com](https://www.jordangrieve.com).

![Home page](public/images/jordan-hero-image.png)

## Stack

- Next.js 15 (App Router), React 19, TypeScript
- The design system's own CSS (`src/styles/nocturne.css`) plus plain CSS. No Tailwind, no CSS-in-JS
- `next/font` for Inter and Anton
- A self-hosted subset of the Phosphor icon font, generated by `scripts/build-icon-font.mjs`
- Every page is prerendered at build time. The contact form is the one thing that needs a server: it posts to a server action, which sends the message through Resend
- Hosted on Railway, behind Cloudflare

## Routes

| Route          | Page |
| -------------- | ---- |
| `/`            | Home |

`robots.txt`, `sitemap.xml`, `llms.txt`, the Open Graph images and the icon set
are all generated routes under `src/app/`.

## What was hard

**Porting a container-query design without redrawing it.** The design was
built inside a fixed-width preview frame with `container-type: inline-size`,
so every measurement is in `cqw` units and its one breakpoint is a container
query at 640px. Rather than translate hundreds of values to viewport units,
`.wrap` in `src/styles/globals.css` plays the frame's role, capped at 1500px
and full-width below that, so the original sizing maths still holds. One
consequence: the mobile drawer is portalled to `document.body`, because
`position: fixed` inside a container-type element resolves against the
container rather than the viewport.

**Icons without a third-party request.** The site used to load the full
Phosphor stylesheet from unpkg: a render-blocking request to another origin
for roughly 1,500 icons, of which about 40 are used. The build script scans
the source for `ph-*` classes, subsets the font to those glyphs and inlines it
as a data URI in `src/styles/phosphor-subset.css`. The generated CSS is
committed, so a normal build needs neither the script nor its dependencies.

**Being findable by name.** Search and answer engines need the full name and
structured data, not a first name and a tagline. `src/lib/schema.ts` builds a
`Person` graph with `knowsAbout`, each case study gets its own generated Open
Graph image, and `llms.txt` describes the site for AI crawlers. The plan and
what each step changed are in `SEO-PLAN.md`.

**Staying usable when the text gets bigger.** Font sizes are in rem and every
padding, margin and gap is in em, so a reader who turns their text size up
gets larger words with proportionally more room round them, not larger words
in boxes that stayed the size they were. That is easy to break one inline
style at a time and impossible to see at the default size, so
`scripts/check-font-units.mjs` runs before every build and fails it on a px
font size or px spacing. Borders, radii, fixed box sizes and breakpoints are
still px.

The layout is checked at 150% zoom, at 150% text, and down to a 240px-wide
screen, which is where it kept breaking. Three things caused nearly all of it,
and each has a comment at the fix in `globals.css`: grid tracks with a fixed
minimum width wider than the screen; elements sized in different units that
only collide once one of them scales (the hero tagline in `ch`, the word
beside it in `cqw`); and a single long word wider than its column. Where a
breakpoint depends on how wide some text is, it is written in rem so that it
moves with the reader's text size.

**Semantics a screen reader can use.** One h1 per page and no skipped heading
levels; lists, description lists and landmarks where the content is one; a
skip link; icons hidden from the accessibility tree; links that open a new tab
saying so. The services accordion and the toolkit tooltips follow the standard
ARIA patterns, and the contact form ties an error to the field it is about and
keeps what was typed when a send fails. Every page passed axe-core at desktop
and phone widths when that work was done. It has not been tested with a real
screen reader.

## Where the content lives

All copy is plain TypeScript under `src/data/`. Edit there, not in the components.

| File              | Contents |
| ----------------- | -------- |
| `site.ts`         | Name, role, email, nav items, social links, the CV |
| `home.ts`         | Hero stats, services, toolkit, about timeline |
| `projects.ts`     | Projects, filters, featured selection, case-study bodies |
| `heroImages.ts`   | Case-study artwork |
| `posts.ts`        | Blog posts: title, date, summary, hero image |

A project with no matching case study 404s rather than rendering a stub, so
add both together.

A blog post's body is the exception to "all copy is data": it is a component
under `src/content/posts/`, registered by slug in `index.tsx` there. A post
listed in `posts.ts` with no body registered renders a one-line "still in
drafts" stub.

## Run locally

```bash
npm install
npm run dev
```

Open http://localhost:3000. After adding or removing a `ph-*` icon class, run
`npm run build:icons` and commit the regenerated CSS.

The contact form needs `RESEND_API_KEY`. Copy `.env.example` to `.env.local`
and fill it in; without it the form renders but every send returns an error.

| Command | What it does |
| ------- | ------------ |
| `npm run dev` | Dev server |
| `npm run build` | Runs the unit check, then the production build |
| `npm run check:fonts` | The unit check on its own |
| `npm run lint` | ESLint |
| `npm run build:icons` | Regenerates the icon font subset |
